Puppy3D

A small C++17 desktop editor and prototype 3D game engine, built with GTK 3, OpenGL 3.2, libepoxy, SDL2_mixer, and Lua 5.4.

Developer documentation

For a source-by-source guide to the engine and practical notes on modifying GTK, OpenGL/libepoxy, SDL2_mixer, input, scene files, GLB imports, and Lua, see the Puppy3D developer documentation.

Build and run

Install the platform dependencies with the included setup script:

setup-windows-mingw.bat
bash setup-ubuntu.sh
bash setup-fedora.sh
bash setup-arch.sh
bash setup-suse.sh

The Windows script installs packages through MSYS2 and defaults to C:\msys64; set MSYS2_ROOT if MSYS2 is installed elsewhere. Run make from an MSYS2 MINGW64 shell. On Linux, run make in the project directory after the matching setup script.

Alternatively, install the Windows dependencies directly from an MSYS2 MINGW64 shell:

pacman -S --needed mingw-w64-x86_64-gcc mingw-w64-x86_64-make mingw-w64-x86_64-pkgconf mingw-w64-x86_64-gtk3 mingw-w64-x86_64-SDL2 mingw-w64-x86_64-SDL2_mixer mingw-w64-x86_64-fluidsynth mingw-w64-x86_64-lua54 mingw-w64-x86_64-nlohmann-json mingw-w64-x86_64-libepoxy

Build from the project directory:

make
make run
make test
make clean

The executable is written to export/windows/bin/Puppy3D.exe on Windows and export/linux/bin/Puppy3D on Linux. The build copies project resources beside it into the corresponding res/ folder.

Editor

  • The Resources sidebar browses the res/ asset tree. Double-click a text file to open it.
  • The File Editor supports creating, opening, editing, and saving UTF-8 text files. Binary files are read-only; files over 8 MiB are not opened in the text editor.
  • The Properties panel shows the selected resource's name, path, type, and size.
  • The 3D View tab uses a GTK OpenGL 3.2 core context, libepoxy, and GLSL shaders. Drag the panel handles to detach Resources, Object Explorer, or Properties into independent windows.
  • Select an audio asset and use Play Audio or Stop Audio. SDL2_mixer supports common formats such as WAV, OGG, MP3, and FLAC. MIDI playback uses FluidSynth and the SoundFont at res/sf2/gm.sf2; it is disabled when either the backend or soundfont is unavailable.

Viewport and object editing

  • Click the 3D View and use W/S to move forward/back, A/D to strafe, E to rise, and Q to descend.
  • Hold the right mouse button and drag to orbit the camera. Left-click an object to select it in Object Explorer.
  • In Properties, choose Move, Rotate, or Scale, then press the axis arrow buttons. Each click moves by 0.25 units, rotates by 5 degrees, or scales by 0.1.
  • Enable Edit Cube Vertices, select vertex 0–7, and edit its local X/Y/Z coordinates. The viewport displays the cube's vertex handles; edited vertices are saved in scene XML.

Vertex editing currently applies to cubes. Object picking uses approximate bounds, so clicks near overlapping objects may select the wrong object.

Keyboard and gamepad input

The editor forwards its window's keyboard events to the input service and polls SDL2 GameController devices while the editor runs. Controllers can be connected or removed while the editor is open. Keyboard state is cleared when the editor loses focus.

  • W/Up: forward; S/Down: backward; A/Left: left; D/Right: right.
  • Space: jump; Enter: confirm; Escape: cancel.
  • Gamepad left stick and D-pad move; A jumps, Start confirms, and B cancels.

Lua scripts can read input during update(delta_time):

function update(delta_time)
    if input.is_down("jump") then
        -- React to the held jump action.
    end
    local horizontal = input.axis("move_x")
    local forward = input.axis("move_y")
    local has_gamepad = input.gamepad_connected()
end

input.is_down(name) supports forward, backward/back, left, right, jump, confirm, and cancel. input.axis(name) supports move_x and move_y, returning values clamped to -1..1 with a gamepad stick dead zone. input.gamepad_connected() reports whether a recognized SDL game controller is connected.

Importing GLB models

Use Import GLB to choose a glTF 2.0 binary .glb model. You can also double-click a .glb file in the Resources tree. Imported models become scene objects and appear in the scene outliner. Save Scene stores references to the source models rather than copying them.

The importer supports triangle primitives, indexed or non-indexed meshes, node transforms, normals (or generated normals), and the first UV set (TEXCOORD_0). It imports PBR base-color factors and base-color PNG/JPEG textures, including images embedded in the GLB. External image and buffer URIs are resolved relative to the model file.

Select a model with animation clips, choose a clip in the Animation inspector, then use Play/Pause or drag the timeline to preview it. Translation, rotation, and scale channels with STEP, LINEAR, and CUBICSPLINE interpolation are supported.

Additional glTF material maps (metallic/roughness, normal, occlusion, and emissive), skeletal skinning, morph targets, Draco compression, and required glTF extensions are not implemented. Only triangle primitives are rendered. Texture images are limited to 8192 pixels per side and 64 megapixels.

XML scene modeling

Use Add Cube or Import GLB to build a level. Select objects in the Scene Objects outliner and edit position, rotation, scale, and name in the inspector. Save Scene writes a versioned XML scene; Open Scene restores cubes and referenced GLB models. Model paths are saved relative to the scene file when possible.

The editor supports local vertex editing for cube corners and stores those coordinates in version 1 scene XML. Older XML files continue to load with the standard cube corners. GLB mesh vertices are not editable; sculpting and material authoring are also not provided.

<scene version="1">
  <object type="cube" name="Floor" x="0" y="-1" z="0"
          rx="0" ry="0" rz="0" sx="8" sy="0.2" sz="8" />
  <object type="model" name="Prop" source="models/prop.glb"
          x="2" y="0" z="1" rx="0" ry="45" rz="0" sx="1" sy="1" sz="1" />
</scene>

Lua scripting

Open a .lua file and click Run Lua. The script is executed in the embedded Lua 5.4 runtime; if it defines update(delta_time), that function is called by the editor's frame timer. The bundled example is res/lua/demo.lua.

engine.clear_scene()
local cube = engine.add_cube("My cube", 0, 0, 0)
engine.set_color(cube, 0.25, 0.65, 0.95)
local angle = 0

function update(delta_time)
    angle = (angle + 45 * delta_time) % 360
    engine.set_rotation(cube, 20, angle, 0)
end
  • engine.clear_scene() removes scene objects and imported meshes.
  • engine.add_cube(name, x, y, z) creates a cube and returns its integer ID.
  • engine.set_position(id, x, y, z) sets a cube's position.
  • engine.set_rotation(id, x, y, z) sets its Euler rotation in degrees.
  • engine.set_color(id, r, g, b) sets its RGB color; components are clamped to 0–1.

The Lua runtime exposes base, table, string, math, and UTF-8 libraries, plus the engine API. It does not expose file-loading helpers such as dofile and loadfile.

Project layout

  • src/Editor/ — GTK editor, file editing, audio controls, and frame callbacks.
  • src/Engine/ — scene objects, OpenGL lifecycle, and model integration.
  • src/Importing/ — GLB parsing, images, mesh data, and animation import.
  • src/Input/, src/Scripting/, and src/Scene/ — input service, Lua runtime, and XML scene documents.
  • src/Rendering/ — converts EngineVar polygons into indexed meshes for rendering.
  • src/EngineVariables/ and src/GeneralPuppy3dObjects/ — geometry values and transformable object classes.
  • setup-*.sh and setup-windows-mingw.bat — platform dependency installers.
  • res/ — images, data, scripts, and other project assets.
  • export/linux/bin/res/ and export/windows/bin/res/ — platform resource copies produced by the Makefile.
  • src/Scene/SceneDocument.cpp — XML scene serialization and model reference loading.
  • tests/SceneDocumentTest.cpp — XML round-trip, polygon mesh conversion, and animated GLB integration coverage.
